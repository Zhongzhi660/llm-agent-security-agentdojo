The agent we studied

AgentDojo tool agent — task, input, output

Task: carry out a user instruction by calling domain tools in a stateful sandbox (banking, workspace, slack, travel).

Input
user prompt + tool schemas + the environment state the tools read/write
Output
a sequence of tool calls + a final natural-language answer

Example (banking): "Pay the bill 'bill-december-2023.txt'" → read_file → get_scheduled_transactions → send_money → answer.

The agent we studied

Modules & inference pipeline

SystemMessage → InitQuery → LLM → ToolsExecutionLoop( ToolsExecutor + LLM ) [ + optional defense ]
  • LLM: OpenAI-style chat + function calling (we point it at GPT-6.1-terra / Qwen3.6-flash via a relay).
  • ToolsExecutor: runs each requested tool against the sandbox, appends the result as a tool message.
  • Loop: LLM → tools → LLM … until no tool call, then final answer.
  • Where injection enters: attacker-controlled text inside a tool-returned field (a file, an email, a transaction memo).

The risk

Attack category: indirect prompt injection

A data/control confusion: the LLM reads attacker text that arrived as data (a tool result) and treats it as an instruction. "Indirect" = the attacker never talks to the agent directly; they plant text the agent will later read.

Prior work (AgentDojo, InjecAgent) reports high attack success on 2024-era models with loud templates like "<INFORMATION> ignore previous instructions…".
The risk

Threat model

Attacker
a third party who controls one piece of external data the agent will read (an email, a file, a transaction memo). No access to the system prompt, weights, or the user.
Victim
the user who delegates a task to the agent.
Objective
make the agent call a sensitive tool chosen by the attacker (move money / exfiltrate), ideally while still finishing the benign task (stealth).
Capabilities
inject arbitrary text into exactly one tool-returned field; static (not adaptive within an episode).

Our attack · FACA

Idea: stop shouting, blend in

FACA = Failure-feedback Adaptive Context Attack. Don't announce an override. Make the malicious action read like content the user's own task would naturally contain.

  • V5 Task-Aligned — the action is a "related follow-up" inside a record about the user's task.
  • V6 Workflow-Aligned — + a "reconciliation pending" workflow step.
  • V7 Authorization-Claimed — + the record claims it was "approved".

The malicious objective text comes from AgentDojo's injection task; FACA only changes the framing. Single-factor variants let us ablate what matters.

Evaluation

Dataset & metrics

  • Dataset: AgentDojo v1.2.1 — banking/slack/travel/workspace; examples sampled from the banking suite (30 fixed user×injection pairs, 60/20/20 split by user task).
  • Models: GPT-6.1-terra (strong) and Qwen3.6-flash (weak) via an OpenAI-compatible relay.
  • Metrics: ASR (AgentDojo's own security check), Utility, Utility-under-attack, with 95% Wilson CIs.
  • Controls: a benign same-format record (placebo) to rule out keyword/length effects.

The decisive experiment

Same action text, only the source differs

Harmless synthetic field change; T byte-identical in U and R; execution verified by final sandbox state. 20 pairs × 2 reps.

Conclusion

Takeaways

  • Published single-shot injections are largely neutralized on a current frontier model (1/1245).
  • Reframing the payload (FACA V5–V7) does not help: ASR stays 0 on GPT-6.1.
  • Not a delivery/comprehension/executability failure — the model holds a user-authorization boundary: identical action, 100% from the user vs 0% from an untrusted tool return.
  • A weaker model (Qwen3.6-flash) is still breached (40%), proving the attack is real.

Confounder stated honestly: source is entangled with dialogue position; a two-turn, position-matched test is the clean next step.

Conclusion

Next steps & limitations

  • Provenance vs position: run U/R with T placed at a matched decision stage (two-turn) to separate "source" from "it came later".
  • Breadth: more suites (workspace/slack), more weak models, larger N for tighter CIs.
  • From attack to defense: if the boundary is provenance-based, a provenance-tagging defense should preserve it on weak models too.
  • Limitations: one suite for the controls, N=2/pair (sign not precision), heuristic trajectory labels, relay-side content filter noted.
